# Открытие актуальной версии в браузере · 0.1.1

Пользователь сообщил, что в Яндекс Браузере всё ещё нет визуальных изменений и отображается версия 0.1. Все предыдущие сборки имели одинаковую версию 0.1.0; без полного SHA или адреса телефона это не устанавливает причину расхождения.

В изолированном браузере с настоящим старым service worker и двумя вкладками проблема воспроизводится: новая сборка ожидает активации, а обычная перезагрузка снова открывает старый precached HTML. Принудительная активация опасна для ввода в другой старой вкладке, поэтому она не используется.

После сборки Pages создаётся `/auth/v1/open.html` — точная копия итогового `index.html`. Этот путь исключён из navigation fallback уже в старых workers и явно исключён из нового precache. Он открывает свежий HTML и текущие assets из сети в том же браузере, сохраняя origin и хранилища. Открытие не вызывает `skipWaiting`, `unregister` или очистку данных. Уведомление активации worker в этой сессии скрыто: свежий интерфейс уже загружен, а другие старые вкладки могут содержать ввод.

Вход и настройки показывают версию 0.1.1 и фактически запущенный SHA. В настройках есть нативная ссылка «Открыть свежую версию» с уникальным query против HTTP-кеша; SPA Router её не перехватывает. Она требует сохранить формы и блокируется при текущей записи. Сам переход покидает текущую форму, поэтому несохранённый React-ввод нельзя обещать восстановить.

## Проверка

`tests/browser/fresh-entry-audit.mjs`: 6/6 PASS на Chromium с настоящим старым worker, двумя вкладками и новым production build с тестовой конфигурацией. Alias получен из сети; новая версия и SHA видны; worker остаётся ожидающим. Во второй вкладке нет навигации, смены контроллера или потери неотправленного ввода. LocalStorage, IndexedDB, черновик, очередь и конфликт сохранены точно. JavaScript-ошибок нет.

UI входа/настроек проверен на 320/393/443 px в Chromium и WebKit; ссылка имеет высоту 44 px. Физический Яндекс Браузер не проверен.

## Использование и пределы

Сохранить текущий ввод и открыть свежую ссылку онлайн в том же Яндекс Браузере и профиле. Подтверждение — версия 0.1.1 и SHA, показанные приложением. Этот вход обновляет открытый интерфейс, а не принудительно активирует общий worker. Пока старый worker активен, обычная перезагрузка корневой страницы может снова открыть его оболочку; для надёжного входа пользоваться свежей ссылкой. После сохранения и закрытия всех старых вкладок ожидающий worker может активироваться естественно.

В установленной Home Screen PWA другой контейнер хранилища: внешняя ссылка из браузера не доказывает обновление установленного приложения. В этом запросе пользователь указал браузер, а не значок PWA.
