# Достигатор

Отдельное mobile-first web/PWA приложение для жизненных целей, проектов и дисциплины. Оно помогает выбрать конечный результат, разбить его на конкретные действия, держать максимум три главных дела на день, поддерживать привычки и проводить честный недельный обзор.

## Актуальная интеграция продукта — 22.10.2026

Программа V2.1 A/B/C встроена в штатный загрузчик `src/lib/training-program.ts` и реэкспортируется через `trainingRepository`. Она доступна при обычном запуске и сборке, без `VITE_LOCAL_PROGRAM_V21`, тестовых адаптеров или загрузки изменяемых серверных шаблонов. Предпросмотр использует тот же загрузчик и штатный `useTemplates`.

A/B — по 6 упражнений и 15 рабочих подходов, затем по 20 минут кардио; C — 30–45 минут кардио по желанию и необязательные бицепс, трицепс, икры. Состав V2.1: `src/lib/program-v21.json`. История и уже начатые черновики сохраняют свои снимки.

Облачная синхронизация использует атомарные RPC и точные секунды кардио. Перед подключением нового клиента к настоящему backend требуются подготовленные миграции точного кардио и двух новых exercise_key. Они проверены во временной PostgreSQL, к production не применялись. Шесть внешних API-проверок и физическая мобильная приёмка ожидаются; deployment не выполнялся.

Ниже сохранены исторические описания прежних итераций; они не описывают текущий статус программы или точности кардио. Актуальный запуск — `README-local.txt`.

## Локальная итерация 15.10.2026

Проверка без аккаунта и облачной базы: `pnpm install --frozen-lockfile`, затем `pnpm dev:local`. Открыть http://127.0.0.1:4182/training/workout/A.

Вход в `tests/local-browser/` использует реальные страницы приложения, синтетические данные и локальные адаптеры вместо сетевого клиента. Кнопка сети имитирует offline/online для проверки очередей; ресурсы загружаются с localhost. Этот вход не выполняет запросов в Supabase. Обычный `pnpm dev` сохраняет штатный вход приложения.

Рекомендация учитывает все рабочие подходы и два последних факта. Поля повторяют прошлый факт; прибавку пользователь принимает кнопкой «Попробовать». Вес предлагается после двух полных сопоставимых выполнений верхней границы с одинаковым весом и при указанном шаге оборудования (не больше 10% веса). Неизвестный RIR не выдумывается. RIR меньше 2, ухудшение, неполная тренировка, другой диапазон или перерыв от 14 дней блокируют прибавку. Порог перерыва — правило продукта, без физиологических выводов.

Обзор показывает последние 8 недель, включая пустые, минуты кардио и фактические веса/повторы по датам. Итог завершения открывается в истории по UUID и восстанавливается после перезагрузки.

Скорость, уклон и сопротивление сохраняются только на устройстве, с явной пометкой в форме и истории. Они не входят в облачный payload и существующий экспорт. Секунды остаются показанием таймера; история хранит полные минуты с предупреждением перед сохранением. Новых миграций в этой итерации нет.

## Возможности

- цели и проекты по сферам жизни;
- причина цели, срок, прогресс и состояние;
- конкретные следующие действия;
- «Фокус 3» — не больше трёх главных действий на день;
- привычки, недельная норма и текущая серия;
- полноценный TrainLog-модуль: программа A/B/C, библиотека упражнений, подходы, вес, повторения, RIR, разминка, замена и пропуск упражнения;
- проверка готовности, таймер тренировки и отдыха, офлайн-черновик и безопасная синхронизация;
- сравнение каждого рабочего подхода с последним завершённым результатом, индивидуальная цель по весу/повторам/секундам и оценка факта; в облегчённом режиме прибавка не предлагается;
- один активный подход: прошлый факт, план, крупные вес/повторы и одно подтверждение; остальные подходы компактны, есть исправление, локальный пропуск/возврат и защита от двойного нажатия; RIR и оценка готовности необязательны;
- единая консервативная прогрессия: по подтверждённым подходам и диапазону программы, небольшой необязательный шаг только в первом подходе при достаточной истории; произвольные прибавки секунд не предлагаются;
- кардио с восстанавливаемым локальным таймером или ручной записью только фактических минут; дистанция для подходящих активностей, пульс, настройки в заметке и усилие находятся в необязательных деталях; облачная очередь и старые записи сохранены;
- текущая облачная схема хранит целые минуты: секундный таймер показывается отдельно, при сохранении явно подтверждаются полные минуты; секундная история и структурированные скорость/уклон требуют отдельного согласования схемы;
- история тренировок, прогресс по упражнениям, замеры тела, питание, шаги и недельный PDF-отчёт;
- прозрачный индекс дисциплины;
- недельный обзор: победы, препятствия и следующий фокус;
- offline cache и идемпотентная очередь изменений с client UUID;
- JSON-резервная копия и неразрушающее восстановление;
- Supabase Auth: пароль, magic link и восстановление пароля;
- installable PWA.

## Запуск

```bash
pnpm install --frozen-lockfile
cp .env.example .env
pnpm dev
```

В `.env` нужны только браузерные параметры:

```text
VITE_SUPABASE_URL=https://vbxkcvygfakmosjvxjwh.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
```

Secret/service-role key не используется и не должен попадать в `VITE_*`.

## Supabase

Приложение использует существующий project `vbxkcvygfakmosjvxjwh`. Жизненные цели хранятся в таблицах с префиксом `dostigator_`:

- `dostigator_areas`;
- `dostigator_goals`;
- `dostigator_actions`;
- `dostigator_habits`;
- `dostigator_habit_checkins`;
- `dostigator_weekly_reviews`.

Тренировочный модуль использует прежнюю изолированную схему TrainLog:

- `exercise_library`, `workout_templates`, `workout_template_items`;
- `workout_sessions`, `workout_session_exercises`, `workout_sets`;
- `body_measurements`, `nutrition_entries`, `daily_activity`.

Программа A/B/C и техника упражнений загружаются из базы, а не зашиты в интерфейс.

Schema changes находятся только в `supabase/migrations/`. У каждой таблицы включён RLS и есть отдельные SELECT/INSERT/UPDATE/DELETE ownership policies. `anon` не имеет table grants, а frontend не передаёт `user_id` при записи. Composite foreign keys не позволяют привязать действие или привычку к объекту другого пользователя.

### Выпуск тренировочного baseline

`20260825051101_create_trainlog_core_schema.sql` — идемпотентный baseline TrainLog. Его версия совпадает с первой миграцией, уже записанной в production, поэтому чистые окружения получают схему с нуля, а существующее окружение корректно пропускает её при `supabase db push`.

## Offline

Последний снимок данных хранится локально под ключом конкретного Supabase user ID. Новые записи получают UUID на клиенте. При отсутствии сети upsert/delete складываются в очередь, повторяются после события `online` и удаляются только после обработки. Supabase API responses не попадают в Workbox runtime cache.

## Индекс дисциплины

- 50% — выполнение выбранного дневного фокуса;
- 30% — соблюдение привычек;
- 20% — завершённые действия по целям.

Это подсказка для недельного обзора, а не оценка личности.

## Deployment

GitHub Pages workflow собирает приложение с base path `/dostigator/`, выполняет `test:all` и добавляет SPA fallback. Repository secrets:

- `VITE_SUPABASE_URL`;
- `VITE_SUPABASE_PUBLISHABLE_KEY`.

Для Railway подготовлены `Dockerfile`, `Caddyfile` и `railway.json`. Caddy слушает порт `8080`, отдаёт SPA routes и предоставляет `/health`.

В Supabase Authentication → URL Configuration нужно добавить production URL в Site URL/Redirect URLs, включая `/reset-password`.
